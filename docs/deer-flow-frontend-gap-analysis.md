# VD-Flow 前端对齐 Deer-Flow 差异清单

## 结论

这次不是“改几个组件”，而是把当前前端从“单页聊天器”升级成“完整工作区产品”。

当前前端入口几乎全部收敛在 `frontend/src/App.tsx`，本质是单页 SPA 聊天壳。

`deer-flow` 的前端则是完整应用壳，核心是：

- `workspace` 多路由工作区
- 独立 chats 页面
- 独立 agents 页面
- 设置中心
- artifact 工作流
- 官网/文档/博客外围系统

如果目标是“前端对齐 deer-flow”，建议先明确范围：

- 只对齐 `workspace` 工作台
- 暂不包含 landing/docs/blog

否则会把“工作台重构”和“官网体系重建”混在一起，路径不会最短。

## 当前已具备能力

当前前端已经有的能力：

- 线程列表
- 新建对话
- 删除对话
- 模型选择
- 模式切换
- 流式回复展示
- thinking/tool/subagent/token 的基础展示
- 消息中的 artifact 下载链接

这些能力说明当前前端已经有“聊天主链路”，但还没有形成完整产品结构。

## 缺失清单

### P0：工作台骨架级缺失

- 多路由工作台骨架缺失
  当前是单页 SPA；`deer-flow` 是 `workspace/chats`、`workspace/chats/new`、`workspace/agents` 这类信息架构。

- 可折叠工作台侧边栏缺失
  当前只有固定线程栏；缺少工作区头部、折叠态、最近对话区、底部菜单区。

- 独立会话列表页缺失
  `deer-flow` 有专门的 chats 页面和搜索入口；当前只有左侧线程列表。

- 线程管理动作缺失
  缺少重命名、分享、导出 Markdown/JSON、删除后自动跳转下一个线程。

- 聊天页顶栏缺失
  缺少线程标题区、token 指示器、导出入口、artifact 入口。

- “新对话”欢迎态布局缺失
  `deer-flow` 的新线程页不是普通空白页，而是居中欢迎区加浮动输入框。

### P1：聊天体验与工作流缺失

- 输入框能力缺失
  缺少附件上传、附件 chip、建议追问、模式说明、reasoning effort 细粒度控制、线程级上下文持久化。

- 消息渲染层级不足
  缺少消息分组、复制按钮、引用链接、数学公式、代码高亮、图片/文件附件展示、上传文件回显。

- artifact 工作流不完整
  当前只有下载链接；缺少 artifact 列表、详情面板、代码/预览切换、复制、下载、打开新窗口。

- 子任务展示不完整
  当前只有基础分支卡片；缺少可展开的 subtask 卡、过程状态解释、结果内容区。

- Todo 区域缺失
  后端已有 todo 中间件痕迹，但前端没有独立待办面板。

- 通知与后台完成提示缺失
  `deer-flow` 会在页面失焦时给出完成通知。

- 命令面板和全局快捷键缺失
  缺少 `Cmd/Ctrl+K`、新对话、设置、快捷键说明。

### P1：工作区产品能力缺失

- 设置中心整块缺失
  `deer-flow` 有 appearance、memory、tools、skills、notification、about 六大页；当前没有设置系统。

- Agents 产品线缺失
  缺少 agent 列表、创建 agent、agent 专属聊天页。这是当前前端最大的功能空洞之一。

- 主题与 I18n 基础设施缺失
  `deer-flow` 有 theme provider 和多语言结构；当前没有这层抽象。

### P2：外围站点缺失

- 官网首页缺失
- 文档站缺失
- 博客/更新流缺失

这些属于外围系统，不建议和工作台重构同时推进。

## 会卡住的后端前置项

下面这些不是“纯前端重构”，而是前端一旦对齐到 `deer-flow`，会被当前后端接口卡住的点。

- 缺少 `agents` 相关 API
  所以 agent 列表、创建、编辑、专属会话目前做不了。

- 缺少 skills 启用/安装 API
  所以 `deer-flow` 那种技能管理页目前做不了。

- 缺少 MCP 配置 API
  所以工具开关页目前做不了。

- memory API 不完整
  当前只有读取和清空，没有事实级增删改、导入导出，所以完整 memory 设置页做不了。

- 聊天请求仍是纯文本 `message`
  没有上传协议，所以附件上传输入框不能直接照搬。

- 线程后端没有重命名接口
  但已有查询能力，所以“搜索会话”能先做，“重命名会话”需要先补 API。

## 建议的范围收敛

为了走最短路径，建议把重构范围锁成：

### 第一阶段：只对齐 workspace

- 工作台路由骨架
- 侧边栏与 chats 页面
- 聊天页顶栏
- 新对话欢迎态
- artifact 面板
- 更完整的消息展示
- 命令面板
- 基础设置壳

### 第二阶段：补后端再接产品能力

- agents
- skills 管理
- tools/MCP 管理
- 完整 memory 设置
- 附件上传
- 线程重命名/分享

### 第三阶段：外围站点

- landing
- docs
- blog

## 一句话判断

如果目标是“彻底重构前端并对齐 deer-flow”，最合理的定义不是“先换 UI”，而是：

先重建 `workspace` 信息架构，再补齐被后端卡住的产品能力，最后再处理官网和风格色调。
